From a screenshot to a themeable diagram template

Walking one template through the pipeline: start from a reference image, generate design options, pick one per step count, vectorize, and transform it into a component the editor recolors and resizes by content.

01

The reference

A screenshot of the look we want — the only hand-authored input.

02

Generate a batch, keep the cleanest

Gemini · image modelhuman pick

The image model is non-deterministic — every run varies in quality, spacing, and how faithfully it matches the reference. So instead of trusting one output, we generate a batch and a human keeps the cleanest one (highlighted). This is the batch for a single step count.

03

Repeat for every step count

A diagram has to render at different lengths depending on content — a 3-item list, a 5-item list. The model can't reflow one image to fit, so the batch-and-pick from step 2 runs once per step count. These are the kept picks for 3, 4, and 5 steps.

04

Vectorize the picked image

Quiver · vectorize model

The picked raster image is traced into SVG paths. Accurate, but raw — a flat picture with no notion of steps or theming.

05

Transform into a component

deterministic code

A transform re-classifies each vector shape into per-step elements the runtime understands — text slots, themeable shapes, step grouping. This is what turns the flat SVG into a live component, rendered here with real content.

06

Themeable, not static

Because each element is classified during the transform, the runtime recolors and emphasizes per step. The arc rings shade by opacity, so a single theme color reproduces the nested look and still recolors cleanly.
