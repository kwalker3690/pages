Grid representation and editor behavior

This page describes the grid and gridItem node structure, the 60-unit span system, direction and wrapping, derived grid roles, resizing, and structural changes made by cell dragging.

Interactive span example Collection and structure roles

Grid nodes and rendered boxes

The grid computes placement. Each cell owns a geometry frame, a visual surface, and an editable content region.

grid · direction + group layout
gridItem · cell A Cell frame → visual surface → editable content
gridItem · cell B Cell frame → visual surface → nested grid or content
Ownership

Cell frame and cell surface have separate responsibilities

The private cell frame owns pointer geometry, selection state, resize previews, and chrome. The public cell surface owns authored backgrounds, borders, masks, padding, and custom CSS.

  • Chrome stays a sibling of the painted surface, so authored clipping cannot hide it.
  • Only the grid's direct cells participate in its placement calculation.
  • A nested grid starts a new layout context inside its containing cell.
Stored spans are the source data Stored spans describe intent. The layout engine turns them into CSS placement; authors do not write grid-column or grid-row directly.

Span representation and resize behavior

Dragging a seam trades span between adjacent cells while the outer grid edges stay fixed. The preview and commit use the same math.

24 / 36
Cell A 24 units
Cell B 36 units
Document: semantic spans may store one decimal place. Renderer: each semantic unit becomes ten physical CSS tracks, so tenths stay exact without fractional span syntax.
Preview · CSS

Preview writes CSS custom properties

During pointer movement, the editor writes temporary physical-track values directly to CSS custom properties on the affected grid and cell DOM elements. It does not dispatch a ProseMirror transaction on every frame.

Commit

Commit updates document spans

Pointer release writes the semantic spans and restores temporary preview styles before React paints again.

Alignment

Snap targets come from peer seams

Nearby peer-grid seams provide screen-space alignment targets. Cmd/Ctrl bypasses the magnetic snap.

Span contract

Each grid axis uses a 60-unit semantic space

A span is a document value, not a percentage or a CSS track count. Within one flow group, 60 represents the full available axis: 30 is one half, 20 is one third, and 15 is one quarter.

  • Authored and resized spans may use one decimal place.
  • For example, 16.3 + 43.7 = 60.
  • Values are rounded with roundGridSpan before commit.
Axis mapping

The direction determines which span field is the flow axis

  • Horizontal grid: horizontalColumnSpan controls width; horizontalRowSpan is the optional cross-axis height.
  • Vertical grid: verticalRowSpan controls height; verticalColumnSpan is the optional cross-axis width.
  • The next cell wraps when adding its flow span would exceed 60.

Direction, grouping, and wrapping

Cells consume span along the flow axis and wrap when the next cell would exceed 60. The cross axis contains the resulting groups.

The same algorithm is transposed. Explicit row sizes can pin vertical bands; wrapped columns can also trade cross-axis span.

Why flexible grids use cell margins instead of CSS gap The rendered grid is not a two-column CSS grid. A 24 / 36 split uses 600 narrow tracks: cell A spans 240 and cell B spans 360. CSS gap would create 599 gaps, including gaps inside each spanning cell, when the layout needs only one visible gutter between A and B. The renderer sets CSS gap to zero and applies --gml-grid-gap as margins at cell boundaries instead. The cell areas still cover the full grid and its outside edges stay flush.

Collection and structure grid roles

A grid's role is derived from its structure, not stored in the document. It affects selection, growth, arrow navigation, and chrome.

Collection

Collection grid

Used for cells with a repeated structural signature, such as cards, steps, people, or features.

  • Click entry prefers the items.
  • Arrow keys walk between members.
  • The add control grows the set at its end.
  • Grid-level chrome exposes actions for the set.
Structure

Structure grid

Used for unlike regions, such as a heading beside a chart or nested layout scaffolding.

  • Selection emphasizes the direct-cell lattice.
  • Flush nested structures avoid duplicate selection rungs.
  • Cells can expose row, column, or cell labels from their direct shape.
  • A one-cell grid remains structure and has no set-growth control.
Grid role is derived, not authored There is no authored role flag. A classifier derives the role from the grid's cells, signatures, spans, markers, and nesting context, so legacy and imported documents get the same behavior automatically.

Cell drag operations

The target zone determines whether the cell joins a group, creates a group, or splits a peer cell.

join this flow group
new row / column

Deep inside a band joins it. Gutters, outer cross edges, and space beyond the grid create a new full-span group.

Parent peer

Drop onto a parent peer

top / bottom → vertical split
left / right → horizontal split

Dropping onto a direct sibling can create a nested grid that wraps the target content and the moved cell in one transaction.

Selection and interaction ownership

Pointer resolution assigns each interaction to one grid while nested grids may still contribute visible presentation layers.

One grid owns each pointer interaction

Pointer resolution selects one interaction owner while allowing subordinate grids to contribute presentation layers. This keeps nested seams visible without showing competing handles.

Native text surfaces keep the caret

Text ink and blank authored flow space remain native caret territory. Resize seams and exact handle seats win only inside their explicit hit regions.

Temporary layout must be restored after every drag

Live preview writes directly to DOM styles for speed. Cleanup restores the DOM before the document transaction so React never inherits stale placement from an earlier gesture.
