Nested stacking contexts

Cards, cells, and painted content boxes each create a local version of the same background → treatment → content pattern.

Card

Card stacking context

The card fill sits on the root. A background image and optional treatment paint inside the isolated canvas below flow content.

Grid cell

Grid-cell stacking context

A cell background, background image, and tint/frost are clipped to that cell's radius and sit behind its editable content.

Content box

Content-box stacking context

The box background sits at the base, its image at −2, its overlay at −1, and the box's flow content remains in front.

Compare stacking contexts before comparing numeric values A cell's z: −1 treatment is scoped to the cell. A card's z: −1 back layer is scoped to the canvas. Compare the containing stacking context before comparing raw numbers.

Freeform reordering and the flow boundary

Freeform siblings first reorder within their own layer. At the back edge, supported objects can move into the behind-flow layer.

Step 1

Freeform sibling order

Bring forward or send backward changes sibling order at z: 3.

Step 2

Back edge of the freeform layer

The object is adjacent to the flow boundary but still paints above flow.

Step 3

Transition to behindFlow

Sending farther back moves an eligible image or shape to z: −1.

Return

Return to the freeform layer

The frontmost back-layer object crosses upward as the backmost freeform object.

Only images and shapes can use behindFlow Images and shapes can become visual back-layer objects. Text and content boxes stay above flow so document text does not disappear behind other editable document content.

Paint order and hit testing are separate

A behind-flow object is visually covered by flow, but the editor can still recover it through geometry-aware interaction rules.

Text receives native pointer behavior

Clicking or double-clicking actual text over a behind-flow image keeps native caret and word-selection behavior.

Bare area

Bare areas can resolve the underlying object

Empty painted area can select the underlying object even when the browser's DOM target belongs to the flow layer above it.

Deep select

Modifier-assisted deep selection

The modifier-assisted selection path reaches covered canvas objects without giving ordinary text clicks to the freeform engine.

Rendering constraints

These constraints separate authored paint order from overflow feedback and editor-only UI.

Editor chrome must not move layout

Selection rings and controls are overlays or slots. They paint above the document without adding padding, changing box size, or creating an editor-only rendering difference.

Sibling order resolves objects inside one layer

Freeform objects share the same layer value. Their document order is therefore the paint order: later siblings appear on top.

Export and published rendering keep the authored stack

The canvas stacking contract is renderer-owned. Read-only, server-rendered, and published surfaces keep the same authored layer order while omitting editor-only chrome.
