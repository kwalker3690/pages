Canvas-card sizing and content fitting

This page describes the canvas-card render path: how its fixed and fluid modes establish width, how fitting changes layout and type, how display scaling maps the canvas to a viewport, and how each rendering surface handles overflow.

Boundary

General principles and excluded behavior

Two principles are general browser behavior: changing width can reflow text, while uniformly scaling an element preserves its line breaks. The variables and pipeline built on those principles are canvas-card-specific.

  • Legacy CardNodeView fitting is not described here.
  • Legacy card layouts and accent-image behavior are not described here.
  • Fluid canvas cards do not fall back to CardNodeView on any surface.
Fixed and fluid are both canvas-card modes They use the same renderer components and theme units. The mode changes which width, fitting, display, and overflow mechanisms are active.

Fixed and fluid canvas cards use different width constraints

The width constraint determines browser reflow and whether the renderer must fit content into a fixed-height frame.

Canvas · fixed

Fixed card

The native frame stays constant—for example, 1280 × 720 canvas pixels for a 16:9 card. The surface scales that artboard without changing its geometry.

  • Line breaks stay stable when only the display size changes.
  • Layout relief runs before typography is reduced.
  • Presentation and export use the same fixed composition.
Canvas · fluid

Fluid card

The card width tracks its container within a supported band. The browser reflows the content at that real width and the card grows vertically.

  • Text reflows when the container width changes.
  • Container queries can stack or simplify layouts.
  • There is no fixed document-mode frame to overflow.
Display scaling and content fitting are different operations Shrinking the whole card preserves line breaks. Reducing content size inside a held width creates new line breaks and can genuinely fit more content vertically. Those are different operations.

Behavior when available width changes

Narrow the available width. The fixed card remains one composition; the fluid card becomes a narrower document and eventually stacks.

Fitting and display variables

These variables act at different stages. Only the fitting values affect content layout; display scaling affects the rendered card as a whole.

1 · layout

layoutFitScale

Reclaims eligible optional layout space—such as fill-media bands and vertical spacers—before typography is reduced.

authored layout → optional space floor
2 · content

contentFitScale

Reduces typography against the held fixed-card width. Text reflows, so the content can consume less vertical space.

role pt × contentFitScale
3 · display

displayScale

Uniformly maps the entire canvas onto the current surface. It is viewer-specific, does not reflow, and is never persisted.

canvas × displayScale → screen
Distribution

Vertical alignment

Uses leftover space. It moves content but scales nothing.

Residue

Overflow mode

Sets the overflow behavior after fitting: reveal in editing, scroll in present, or clip in export and thumbnails.

Theme

Type scale

Defines the authored point sizes per semantic role. It is a deck design input, not a per-viewer fit operation.

Behavior by rendering surface

Document editing can grow and scroll. Presentation and export must reconcile the card with a bounded frame.

Surface Fixed canvas card Fluid canvas card Overflow residue
Document Uses persisted fit factors, then scales to the editor viewport. Tracks container width and grows with content. Fixed reveals spillover; fluid grows normally.
Present Fits the native frame to both viewport axes. Pins width and performs a viewer-specific present-time fit. Scrolls if content still exceeds the fitting floor.
Export Maps directly to the pinned page dimensions. Pins onto the fixed-format path. Clips or paginates according to the export surface.
Thumbnail Uniformly scales the pinned composition. Pins to the thumbnail width before scaling. Clips to the thumbnail frame.

Implementation constraints

These constraints define which values are authored, derived, or specific to a viewer.

Point units define authored and export size

A 16pt role means 16pt in export. Its on-screen size is the authored value after content fitting, displayed through the viewer's card scale.

Fluid cards skip fixed-card fitting in document mode

The container width already causes real browser reflow. The card grows vertically instead of shrinking its content toward a fixed frame.

Fitting stops at configured minimum values

Once optional layout space and typography reach their floors, the remaining overflow is exposed by the active surface rather than reducing content below those minimums.
