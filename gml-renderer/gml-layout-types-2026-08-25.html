Four ways content can occupy a card

Fluid content reflows. A freeformBlock occupies flow space but keeps a local 2D composition. A card-level positionedBox overlays flow. A <freeform> wrapper declares that the whole card is positioned and should edit like a canvas.

Whole card

<freeform>

The wrapper declares that the card has no flow layer. Every visible content item is a positioned box, so the editor uses canvas interactions instead of text-flow interactions.

Choose by responsibility

Decide who must own placement: the renderer, a local visual unit, an overlay, or the whole card.

01

Does the content read in rows or columns?

Use flow. The renderer can absorb edits, new items, and width changes.

Fluid
02

Does one in-flow unit need exact internal overlap?

Give that unit a local coordinate frame. Keep the rest of the card in flow.

freeformBlock
03

Must one element pin above content that stays in flow?

Use a direct card box. It overlays the flow layer and takes no space from it.

positionedBox
04

Is the whole card one positioned composition?

Wrap the boxes in <freeform>. The card then has no flow layer, and the editor treats it as a canvas rather than a text surface.

Boundary notes

These details prevent four common category errors in GML authoring.

Fluid placement differs from a fluid card

The editor calls an in-flow element “Fluid.” The element can exist on a fixed card or a fluid card.

The cardDimensions: "fluid" setting controls the card frame. It does not create a placement node.

A freeformBlock is a flow block

Its outer frame takes real height and pushes later content. Its members use coordinates only inside that frame.

Use one block for one 2D unit. Do not use a card-sized block as a replacement for a whole-card composition.

A card-level positionedBox is an overlay

The box measures from the true card corner. Card padding does not offset its coordinates.

Later boxes paint above earlier boxes. A box does not move when nearby flow content grows.

Why a whole positioned card uses <freeform>

A set of direct card-level boxes can render the same as boxes inside <freeform>. The wrapper adds no geometry; its purpose is to tell the editor that the entire card is a positioned canvas.

Without the wrapper, clicking empty space can place a text cursor, dragging can start a text selection, and arrow navigation can enter the card's flow. With the wrapper, empty space stays non-textual, dragging makes a marquee selection, and arrow navigation skips the card interior.

Use <freeform> whenever everything on the card is positioned. Keep direct card boxes for the few overlays that coexist with mostly fluid content.
